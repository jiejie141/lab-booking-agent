## 1. 五分钟主线（讲故事，不是报功能）

### ① 30 秒定位（先说清"这是什么、难在哪"）

> "这是一套实验室预约系统，Agent 是它的对话入口，但我的设计立场是
> **Agent 不做单点**：资质、时段、容量、违约这些业务判定全在代码和数据库
> 不变式里，模型挂了系统只是少了对话，业务照跑。难点不在调模型，
> 在**并发正确性**和**边界治理**。"

### ② 对话下单（展示协商阶梯，不是"一问一答"）

控制台 → 学生窗口 → 对话框输入：

```
明天下午两点想用荧光光谱仪两个小时
```

预期：原条件约不到（种子里有一个占用），Agent 给 **3 个备选，每个都标注
放宽了什么**（换设备 / 挪时间）。话术：

> "需求填不满的时候，它不会硬编一个答案，而是把'放宽了哪条约束'明说
> —— 这是可解释性，用户知道自己在接受什么。"

### ③ 故意撞车（机器可读的失败分类）

张伟窗口 → 直接对**同一时段**下单 → `409`，响应体带 `reason=conflict`。

> "所有失败都带机器可读的 reason（七类），前端按 reason 分支，
> 不许去解析中文文案 —— 改一句文案指标就静默错位的事，这个项目从一开始就防。"

### ④ 幂等重发（客户端重试不产生脏数据）

同一个请求**换个时段**再发一次、但带**同一个幂等键** → `200`，
响应带 `replayed=true`，返回的还是原预约。

> "真正的危险不是同时段重复下单（唯一索引会挡），而是**超时重试换了时段**
> —— 那会多出一条用户没打算下的单。这里用 (user_id, key) 部分唯一索引
> 在数据库层兜底，回放首次结果。"

### ⑤ 改期（讲事务顺序）

预约记录 → 「改期」→ 新时段 → 成功。话术：

> "顺序是关键：**先校验并占新坑、成功后再放旧坑**。反过来做的话，
> 取消是不可逆的 —— 新时段抢不到，旧时段也没了。"

### ⑥ 并发正确性（最硬的证据）

另开终端：

```
python main.py loadtest
```

默认 **40 并发抢同一时段**，重复 3 轮 → 每轮**恰好 1 条成功**。

> "不是'我加了锁'，是把时段展开成占用格、压一条部分唯一索引，
> PostgreSQL 再加事务级 advisory lock。应用层判断在并发下必然有窗口，
> 所以这道闸放在数据库层。"

### ⑥.⑤ 令牌撤销（30 秒，当场可验 —— 很有冲击力）

这一段的独特价值：**它展示的是「我发现并修掉了一个测试没覆盖的洞」**。

另开终端（或直接念下面的输出）：

```bash
# 1. 让「李娜」登录，拿到一张令牌
# 2. 管理员停用她的账号
# 3. 用她**停用前**拿到的那张旧令牌访问 —— 应当被拒
```

> 「我审这个项目的时候发现一个洞：**停用账号只挡住了新登录**。
> 令牌是自包含的，验签通过就认账 —— 已经发出去的那张在过期前（默认 2 小时）
> 照样能看预约、能下单。而**原有的测试一直是绿的**，因为它断言的是
> 『新登录 401』，那件事确实是对的 —— 测试没说谎，它只是问错了问题：
> 验证的是『密码还能用吗』，而不是『这个人现在还能操作系统吗』。
>
> 修法是加一个 `token_version` 世代号：签发时写进载荷，鉴权时回查比对，
> 停用 / 降权 / 改口令都自增它。不用黑名单 —— 因为要表达的本来就不是
> 『作废这一张』，而是『该用户的所有旧令牌都作废』，一个整数就够，
> 而且**不需要过期清理任务**。顺带 `logout` 也变成一次自增，白送的。」

**现场对照**（修复前后，同一张旧令牌）：

| 端点 | 修复前 | 修复后 |
|---|---|---|
| `/api/auth/me` | 200 | **401** |
| `/api/reservations` | 200 | **401** |
| `/api/agent/chat` | 200 | **401** |

补的两条回归测试里，第一条**先断言停用前旧令牌可用** ——
这是关键：没有这个前置，断言同样无法证伪，会跟着缺陷一起通过。

### ⑦ 收尾（30 秒工程化盘点）

> "1010 项测试（本地 993 通过 / 17 跳过）、7 个迁移 revision（'给有数据的表加列'逐条演练过）、
> CI 六类作业含 PostgreSQL 真实链路、容器化实机验收、备份恢复演练；
> 可观测性有结构化日志（request_id 串一次请求）、Prometheus 指标和告警规则。
> 仓库开源，数字都能对着 CI 复核。"

## 3. 被追问时的深挖点（问题 → 往哪指）

| 面试官可能问 | 往哪指 |
|---|---|
| "模型挂了怎么办？" | `src/lagent/api.py` 的表单下单接口 + `app_mode=degraded`：系统只剩"对话不可用"，不是"不能预约" |
| "并发为什么放数据库层？" | `src/lagent/domain/booking.py`（占用格 + 条件 UPDATE + rowcount）、`models.py` 的部分唯一索引；测试 `tests/test_concurrency.py` |
| "怎么防 Prompt 注入 / 越权？" | HTTP 冒烟与越权清单 **83/83**（`scripts/smoke_http.py`，真实 uvicorn 进程）；资质判定在代码，模型只做语言层 |
| "评测怎么做的？准确率多少？" | `eval/cases.yaml` + `python main.py eval`。**如实说**：mock 模型下的 14/14 衡量的是链路自洽，不是模型准确率 —— 评测报告里印着这行免责声明；接真实模型要单独跑 |
| "迁移怎么保证不搞坏生产库？" | `tests/test_migrations.py`：先在旧 revision 上**造数据**再升级，断言数据仍在、新列取默认值（0003/0005 都演练过） |
| "多副本部署行吗？" | 如实说：**同机多进程已经解决** —— 设 `LAB_STATE_BACKEND=sqlite` 后会话与限流计数共享一份（WAL），脚本与服务并存、`--workers` 都不会漂移；**跨机器**多副本才需要 Redis，那时 `lagent_state_backend` 指标会立刻暴露。这是**有触发条件的取舍**，不是没想过 |
| "密码/密钥怎么管？" | fail-closed：默认密钥拒绝启动；支持 `LAB_JWT_SECRET_FILE`（Docker secret 约定），读不到文件拒启 |
| "账号怎么开？能自助注册吗？" | 能：`POST /api/auth/register`。三条约束**一起**上 —— 角色强制最低级（请求带 `role` 直接 422，不是静默忽略）、按来源 IP 限流（`LAB_REGISTER_PER_HOUR`，默认 5/h）、成功失败都进审计；`LAB_REGISTRATION_ENABLED=false` 整体关掉回 403。提权仍只走管理员 `user.manage` |
| "单机多进程 / 多 worker 会怎样？" | 设 `LAB_STATE_BACKEND=sqlite` 就稳：会话与限流计数落同一个 WAL 文件，脚本与服务并存、`uvicorn --workers` 都不会各算一份配额。`tests/test_state_store.py` 用**两个独立实例**验证了共享（这正是多进程的等价物） |
| "指标会不会自己骗人？" | 会，而且我踩过：`SqliteSessionStore` 继承内存版，基类先报 `memory`、子类再报 `sqlite`，单副本就出现两条序列、被「状态分裂」告警误判成已扩容。改成后端由**类属性**决定、构造期只报一次，并加了两条回归用例。**组件自报的埋点要保证「一个组件一个进程一条序列」，否则它亲手制造出自己要检测的信号** |

## 4. 翻车预案

| 症状 | 处置 |
|---|---|
| 页面打不开 / 登录 404 | 先看**服务端日志**有没有这条请求：没有 = 不是服务的锅（预览面板代理/缓存），换真浏览器重开 |
| 提示密钥相关拒绝启动 | `.env` 的 `LAB_JWT_SECRET` 没配或用了默认值 —— 这是**故意的**（fail-closed），现场配一个随机串重启，顺带讲 30 秒这个设计 |
| 库状态不对 | `python main.py seed --force`（重建演示数据，30 秒） |
| 现场断网 | 无影响：mock 模式不联网；真模型路径没配 key 会进"引导式表单"降级，**这本身就是一个可展示的降级设计** |
| 全崩了 | 放提前录好的 2 分钟录像，说"环境问题我回去查，功能是这样"，继续讲设计 |

## 6. 2026-09-29 新增能力的演示（主线之外，按时间挑）

这一节是**选演**：主线那 7 幕已经够满，下面这些按面试官的兴趣挑 1~2 个。
但既然做出来了，不提等于不存在。

### ⓪ 数据是活的：自动刷新 + 最后更新时间

停在这个页面不动，指一下面板标题右侧的「更新于 19:52:31」。

> "这些数字不是打开那一刻的快照。审批、预约这两个面板每 30 秒自己拉一次，
> 而且**标了这次是什么时候的数据**。改版前要手点才更新 ——
> 管理员的判断建立在过期的数字上，这在后台系统里是很危险的。"

真要现场证明，就另开一个终端跑 `python main.py sweep`，然后等 30 秒 —— 数字会自己变。

### ① 批量审批：N 次点击压成 1 次

⚠️ **前提**：种子默认**一条待审批都不造**（`seed_pending_reservations=0`），
审批面板打开是空的。要演这条，建库时带 `--pending 8`（或环境变量
`LAB_SEED_PENDING_RESERVATIONS=8`）—— 它会自动开一台"需审批"的设备，
否则"要 8 条待办却没有需审批设备"是配置矛盾，会静默产出 0 条。

管理员窗口 → 审批面板 → 勾几条 → 「批量通过」。

> "待办一多，逐条点是最典型的机械重复。
> 注意这里**不是事务**：能批几条批几条，失败的**逐条报原因**。
> 批量审批里的失败多半是'这条恰好在别人手里'，整批回滚反而会让管理员
> 以为一条都没批 —— 这和下单是两种语义。"

### ② 导出：数据能带走

预约面板 → 「导出 CSV」→ 用 Excel 打开。

> "带 BOM 的 UTF-8，Excel 直接打开不乱码。
> 而且导出复用列表那段权限判断 —— **导出是最容易漏掉权限的一类接口**，
> 另写一份 scope 逻辑迟早会走偏。"

（可以让面试官自己看一眼：拿李娜的令牌导出，里面不会有张伟的预约。）

### ③ 对话流式：等待变成可见的进展

在李娜的窗口发一句：

```
明天下午两点想用荧光光谱仪两个小时
```

盯着气泡里逐行冒出来的「正在理解你的需求…」「正在查可用时段与设备…」「正在下单…」。

> "总耗时没变，但等待变成了可见的进展。
> 用 fetch + ReadableStream 逐块读 SSE 而不是 EventSource ——
> 后者只支持 GET，把用户那句话塞进查询串既受长度限制又会进访问日志。"

右上角还有「停止生成」可以现场掐掉一次。

### ④ 手动重发失败通知

如果面到"通知发不出去怎么办"：

> "这块有一条**刻意不自动重发**的取舍：一封迟到的『预约成功』比没有更糟 ——
> 用户照着它去了实验室，而预约早被取消了。所以只有手动入口：
> `python main.py notify --retry-failed`。
> 老实说这个入口原设计里写了、但一直没建，是这轮才补上的。"

### ⑤ 用户规模与角色层级（被问"就这么几个人？"时）

这是**最容易被问到**的一条，主动讲反而加分。默认只灌 4 个演示账号，
但那不是"系统里只有 4 个人"：

```bash
python main.py seed --force --extra-users 200 --pending 8
```

> "演示账号刻意只有 4 个 —— 每个都证明一条不同边界：张伟证明资质约束、
> 李娜证明能约到他约不到的、管理员证明越权边界、系统管理员证明**角色层级**。
> 真正要看规模，数量是配置项：`--extra-users 200` 就有了 204 个账号。
> 合成账号共用口令 `demo@123` 且按固定种子生成 —— scrypt 一次 140ms，
> 500 个不同口令要 70 秒，共用口令只需算一次。
>
> 而且它们不是一堆同质账号：约 5% 没有基础安全资质（进不了任何房间）、
> 5% 资质过期（提示'该复训'）、5% 资质被撤销（提示'被停权'）——
> **三种失败是三句不同的话**，这才是演示价值。"

**角色层级这句一定要说**（它回答了"sysadmin 和 admin 有什么区别"）：

> "原先代码里声明了三个角色，但 `is_admin` 把 admin 和 sysadmin
> 折成了同一个布尔值 —— 三级角色只存在于类型标注里。
> 现在角色有**等级**（用于比较）和**能力点**（用于判定），
> sysadmin 独有一项 `role.manage`：只有它能决定谁是管理员。
> 相应地加了一条提权不变量：**不能把别人设成不低于自己的角色**。
> 这条漏掉的后果最重 —— 任何 admin 都能把自己提权成 sysadmin；
> 而因为两者原本同权，**漏了也看不出来**。
> 我专门写了一个测试钉它：sysadmin 必须至少有一项 admin 没有的能力，
> 它要是红了就说明层级又被拍平了。"

现场可验证（不用讲，直接敲）：

```bash
# admin 想把人设成 admin → 403 role_escalation
curl -X POST localhost:8200/api/users -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"username":"越权","email":"e@example.com","role":"admin","password":"long-enough"}'
# 换成 sysadmin 的令牌 → 201
```
