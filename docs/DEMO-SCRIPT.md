## 1. 五分钟主线（讲故事，不是报功能）

### ① 30 秒定位（先说清"这是什么、难在哪"）

> "这是一套实验室预约系统，Agent 是它的对话入口，但我的设计立场是
> **Agent 不做单点**：资质、时段、容量、违约这些业务判定全在代码和数据库
> 不变式里，模型挂了系统只是少了对话，业务照跑。难点不在调模型，
> 在**并发正确性**和**边界治理**。"

### ② 对话下单（展示协商阶梯，不是"一问一答"）

控制台 → 学生窗口 → 对话框输入：

```
明天下午两点想用荧光光谱仪两个小时
```

预期：原条件约不到（种子里有一个占用），Agent 给 **3 个备选，每个都标注
放宽了什么**（换设备 / 挪时间）。话术：

> "需求填不满的时候，它不会硬编一个答案，而是把'放宽了哪条约束'明说
> —— 这是可解释性，用户知道自己在接受什么。"

### ③ 故意撞车（机器可读的失败分类）

张伟窗口 → 直接对**同一时段**下单 → `409`，响应体带 `reason=conflict`。

> "所有失败都带机器可读的 reason（七类），前端按 reason 分支，
> 不许去解析中文文案 —— 改一句文案指标就静默错位的事，这个项目从一开始就防。"

### ④ 幂等重发（客户端重试不产生脏数据）

同一个请求**换个时段**再发一次、但带**同一个幂等键** → `200`，
响应带 `replayed=true`，返回的还是原预约。

> "真正的危险不是同时段重复下单（唯一索引会挡），而是**超时重试换了时段**
> —— 那会多出一条用户没打算下的单。这里用 (user_id, key) 部分唯一索引
> 在数据库层兜底，回放首次结果。"

### ⑤ 改期（讲事务顺序）

预约记录 → 「改期」→ 新时段 → 成功。话术：

> "顺序是关键：**先校验并占新坑、成功后再放旧坑**。反过来做的话，
> 取消是不可逆的 —— 新时段抢不到，旧时段也没了。"

### ⑥ 并发正确性（最硬的证据）

另开终端：

```
python main.py loadtest
```

默认 **40 并发抢同一时段**，重复 3 轮 → 每轮**恰好 1 条成功**。

> "不是'我加了锁'，是把时段展开成占用格、压一条部分唯一索引，
> PostgreSQL 再加事务级 advisory lock。应用层判断在并发下必然有窗口，
> 所以这道闸放在数据库层。"

### ⑦ 收尾（30 秒工程化盘点）

> "964 项测试、6 个迁移 revision（'给有数据的表加列'逐条演练过）、
> CI 四类作业含 PostgreSQL 真实链路、容器化实机验收、备份恢复演练；
> 可观测性有结构化日志（request_id 串一次请求）、Prometheus 指标和告警规则。
> 仓库开源，数字都能对着 CI 复核。"

## 3. 被追问时的深挖点（问题 → 往哪指）

| 面试官可能问 | 往哪指 |
|---|---|
| "模型挂了怎么办？" | `src/lagent/api.py` 的表单下单接口 + `app_mode=degraded`：系统只剩"对话不可用"，不是"不能预约" |
| "并发为什么放数据库层？" | `src/lagent/domain/booking.py`（占用格 + 条件 UPDATE + rowcount）、`models.py` 的部分唯一索引；测试 `tests/test_concurrency.py` |
| "怎么防 Prompt 注入 / 越权？" | HTTP 冒烟与越权清单 **84/84**（`scripts/smoke_http.py`，真实 uvicorn 进程）；资质判定在代码，模型只做语言层 |
| "评测怎么做的？准确率多少？" | `eval/cases.yaml` + `python main.py eval`。**如实说**：mock 模型下的 14/14 衡量的是链路自洽，不是模型准确率 —— 评测报告里印着这行免责声明；接真实模型要单独跑 |
| "迁移怎么保证不搞坏生产库？" | `tests/test_migrations.py`：先在旧 revision 上**造数据**再升级，断言数据仍在、新列取默认值（0003/0005 都演练过） |
| "多副本部署行吗？" | 如实说：限流与会话目前是进程内的，单副本没问题；已埋了 `lagent_state_backend` 指标，多副本时它会立刻暴露，届时换 Redis —— 这是**有触发条件的取舍**，不是没想过 |
| "密码/密钥怎么管？" | fail-closed：默认密钥拒绝启动；支持 `LAB_JWT_SECRET_FILE`（Docker secret 约定），读不到文件拒启 |

## 4. 翻车预案

| 症状 | 处置 |
|---|---|
| 页面打不开 / 登录 404 | 先看**服务端日志**有没有这条请求：没有 = 不是服务的锅（预览面板代理/缓存），换真浏览器重开 |
| 提示密钥相关拒绝启动 | `.env` 的 `LAB_JWT_SECRET` 没配或用了默认值 —— 这是**故意的**（fail-closed），现场配一个随机串重启，顺带讲 30 秒这个设计 |
| 库状态不对 | `python main.py seed --force`（重建演示数据，30 秒） |
| 现场断网 | 无影响：mock 模式不联网；真模型路径没配 key 会进"引导式表单"降级，**这本身就是一个可展示的降级设计** |
| 全崩了 | 放提前录好的 2 分钟录像，说"环境问题我回去查，功能是这样"，继续讲设计 |

   主动区分"链路自洽"和"模型能力"，是这份简历最值钱的诚实。
2. **不要现场改代码修 bug** —— 修不好就是双倍减分；用录像兜底。
3. **不要报一个自己没跑过的数字** —— 所有数字见下表，说之前扫一眼。

## 6. 2026-09-29 新增能力的演示（主线之外，按时间挑）

这一节是**选演**：主线那 7 幕已经够满，下面这些按面试官的兴趣挑 1~2 个。
但既然做出来了，不提等于不存在。

### ⓪ 数据是活的：自动刷新 + 最后更新时间

停在这个页面不动，指一下面板标题右侧的「更新于 19:52:31」。

> "这些数字不是打开那一刻的快照。审批、预约这两个面板每 30 秒自己拉一次，
> 而且**标了这次是什么时候的数据**。改版前要手点才更新 ——
> 管理员的判断建立在过期的数字上，这在后台系统里是很危险的。"

真要现场证明，就另开一个终端跑 `python main.py sweep`，然后等 30 秒 —— 数字会自己变。

### ① 批量审批：N 次点击压成 1 次

管理员窗口 → 审批面板 → 勾几条 → 「批量通过」。

> "待办一多，逐条点是最典型的机械重复。
> 注意这里**不是事务**：能批几条批几条，失败的**逐条报原因**。
> 批量审批里的失败多半是'这条恰好在别人手里'，整批回滚反而会让管理员
> 以为一条都没批 —— 这和下单是两种语义。"

### ② 导出：数据能带走

预约面板 → 「导出 CSV」→ 用 Excel 打开。

> "带 BOM 的 UTF-8，Excel 直接打开不乱码。
> 而且导出复用列表那段权限判断 —— **导出是最容易漏掉权限的一类接口**，
> 另写一份 scope 逻辑迟早会走偏。"

（可以让面试官自己看一眼：拿李娜的令牌导出，里面不会有张伟的预约。）

### ③ 对话流式：等待变成可见的进展

在李娜的窗口发一句：

```
明天下午两点想用荧光光谱仪两个小时
```

盯着气泡里逐行冒出来的「正在理解你的需求…」「正在查可用时段与设备…」「正在下单…」。

> "总耗时没变，但等待变成了可见的进展。
> 用 fetch + ReadableStream 逐块读 SSE 而不是 EventSource ——
> 后者只支持 GET，把用户那句话塞进查询串既受长度限制又会进访问日志。"

右上角还有「停止生成」可以现场掐掉一次。

### ④ 手动重发失败通知

如果面到"通知发不出去怎么办"：

> "这块有一条**刻意不自动重发**的取舍：一封迟到的『预约成功』比没有更糟 ——
> 用户照着它去了实验室，而预约早被取消了。所以只有手动入口：
> `python main.py notify --retry-failed`。
> 老实说这个入口原设计里写了、但一直没建，是这轮才补上的。"
